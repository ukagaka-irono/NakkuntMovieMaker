# 描画の設計（GPU 版）

M2 で入れた GPU 版の描画（`src/NakkuntMovieMaker.Rendering.Vulkan`）の要点です。CPU 版（`SkiaCpuBackend`）は「正しい結果」を出す基準として残し、GPU 版はそれと比べて確かめます。

## 流れ

1. 呼び出したスレッドで、ノードを GPU の処理にする（`VulkanBackend.Prepare`）。
   - エフェクトのない画像・動画：素材の画素をそのまま GPU に送り、合成のシェーダー（`composite.slang`）で重ねる。
   - エフェクトのあるノード：中身を CPU 版と同じ細かさの画像にし、エフェクトは GPU でかける（`GpuEffects`）。静止したものは、エフェクトをかけた結果を GPU に覚えておく。
   - トランジション：前後のアイテムを、それぞれ出力と同じ大きさの透明な作業用の画像に描いてから、GPU で混ぜる（`GpuTransitions`）。
   - それ以外（文字・図形・立ち絵など）：描かれる範囲だけ CPU で描いて送る。
2. GPU のスレッド（`GpuScheduler`、1 本）で、作業用の画像に順に重ね、BGRA にして読み戻す。

## 作業用の画像

- premultiplied の RGBA を、16 ビット浮動小数点で持ちます。
- どの GPU（MoltenVK・lavapipe を含む）でも動くように、画像ではなくバッファーに入れます（1 画素 8 バイト）。
- 16 ビット浮動小数点への変換は整数の演算だけで行い、SPIR-V の Float16・Int16 の機能は使いません（`SpirvTests` で確かめています）。

## CPU 版と合わせていること

- ぼかしは、Skia の CPU 版と同じく、3 回の箱型のぼかし（SVG の feGaussianBlur の方法）です。箱の幅は `floor(σ·3·√(2π)/4 + 0.5)` で、1 以下ならぼかしません。
- 縁取りの距離変換は、CPU 版と同じ方法（Felzenszwalb と Huttenlocher）を、列ごと・行ごとに GPU で行います。
- モザイクのブロックの分け方は、CPU で表にしてから GPU に渡します。
- 不透明度は、Skia と同じく 1/255 の単位に丸めます。

## 比べるときの基準

`ParityTests` は、ゴールデン画像の 28 の場面を、同じプロセスで CPU 版と GPU 版で描いて比べます。
GPU 版は 16 ビット浮動小数点で計算し、途中で 8 ビットに丸めないので、少しだけ違います。

| 場面 | 基準（PSNR） | 基準の PC での結果 |
| --- | ---: | ---: |
| 合成・文字・図形・色のエフェクト・モザイク・シャープ | 45dB 以上 | 51.9〜∞ |
| 縁取り | 42dB 以上 | 71.7 |
| ぼかし・影・発光・マスク・振動 | 38dB 以上 | 46.0〜69.0 |
| トランジション | 42dB 以上 | 51.8〜∞ |

調べるときは、`NMM_PARITY_DUMP` にフォルダーを指定すると、両方の画像を PNG で書き出します。

## 方式の選び方

- 自動（既定）では GPU を試します。ソフトウェアの Vulkan しかないとき、自己テスト（`GpuSelfTest`）に通らないとき、前回 GPU の準備の途中で止まったとき（目印のファイル）は、CPU で描きます。
- 描いている途中で GPU が使えなくなったら、CPU に切り替えます（`FallbackBackend`）。
- `nmm` の `--renderer`（`auto`・`cpu`・`vulkan`）で選べます。環境変数 `NMM_VULKAN_DISABLE=1` で GPU を使わないようにできます。

## 色（M2 の手順 E）

- **合成の色空間**（プロジェクトの設定）
  - 既定は sRGB です（M1 と同じ見た目）。
  - リニアにすると、作業用の画像をリニアの Rec.709 にし、重ねる・混ぜる・トランジションをリニアで計算します。黒から白への 50% のクロスフェードは、sRGB で 128、リニアで 188 になります。
  - 素材・文字・図形の色と、エフェクトの中の計算（色の処理・ぼかし）は、どちらのモードでも sRGB のままです。
- **OpenColorIO**（`NakkuntMovieMaker.ColorManagement`、ネイティブは `nmm_ocio`）
  - 構成は OCIO に組み込まれた ACES の構成を、版付きの名前で使います（既定は OCIO の既定の構成）。
  - 変換は `BakedColorLut` で、シェーパー（√x を等間隔に並べた 4096 の表）と 65³ の 3D LUT に焼いて、CPU と GPU で同じように引きます。格子に出力をそのまま入れたものと、リニアに戻して入れたもの（引いたあとで sRGB の伝達関数をかける）を作り、誤差の小さいほうを使います。
  - SDR の変換は、OCIO そのものとの差が 2/1023 以内です。PQ のトーンマップ（ACES 2.0 の HDR 1000 nits → SDR）は、色域の境界の近くで急に曲がるので、99% の色で 27/1023 以内です。
- **変換をかける場所**

| 場所 | 設定 | 処理 |
| --- | --- | --- |
| 入力 | 素材ごとの入力の色空間（`Asset.ColorSpace`） | 素材を読んだときに、作業用の sRGB にする（HDR はトーンマップ）。CPU で変換してから描画に渡す |
| 表示 | 利用者ごとの設定（`AppSettings.PreviewColorSpace`） | プレビューの描き終えた画像にかける |
| 出力 | プロジェクトの設定（`ExportColorSpace`） | 書き出す画像にかける |

- どれも、指定がなければ変換しません（OpenColorIO がなくても、M1 と同じに描けます）。
- 表示と出力の変換は、CPU 版は描き終えた 8 ビットの画像に、GPU 版は読み戻す前（16 ビット浮動小数点のまま）にかけます。GPU 版と CPU 版の差は 51dB 以上です（`output/*` の場面）。
